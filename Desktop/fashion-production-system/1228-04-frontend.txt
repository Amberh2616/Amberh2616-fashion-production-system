### 3. React Query Hook (✅ DONE)

**Added Hook:**

```typescript
/**
 * Duplicate CostSheet with new margin/wastage (Phase 2-2I: Version Policy)
 * Creates new version without rebuilding from BOM
 */
export function useDuplicateCostSheet(costSheetId: number, revisionId: string) {
  const queryClient = useQueryClient();

  return useMutation({
    mutationFn: (payload: DuplicateCostSheetPayload) =>
      duplicateCostSheet(costSheetId, payload),
    onSuccess: (data) => {
      // Invalidate list to show new version
      queryClient.invalidateQueries({ queryKey: ['cost-sheets', revisionId] });
      // Update detail cache for new version
      queryClient.setQueryData(['cost-sheet', data.id], data);
    },
  });
}
```

**Cache Strategy:**
- 成功後 invalidate cost-sheets list（顯示新版本）
- 更新新版本的 detail cache（避免重新 fetch）

**Purpose:**
- React Query 狀態管理
- 自動 cache invalidation
- 樂觀更新支援

### 4. Smart Button UI (✅ DONE)

**核心邏輯:**

#### A. 髒欄位偵測（Dirty Field Detection）
```typescript
// Watch all form fields
const formValues = watch();

// Detect dirty fields
const dirtyFields = useMemo(() => {
  const dirty: string[] = [];
  Object.keys(formValues).forEach((key) => {
    const formValue = formValues[key as keyof FormData];
    const originalValue = costSheet[key as keyof CostSheetDetail];
    if (formValue !== originalValue) {
      dirty.push(key);
    }
  });
  return dirty;
}, [formValues, costSheet]);
```

**工作原理:**
- `watch()` 監聽所有表單欄位變化
- `useMemo` 即時計算哪些欄位被修改
- 回傳 dirty field 陣列（例如：`['labor_cost', 'margin_pct']`）

---

#### B. B 欄位判斷（B-Field Detection）
```typescript
const B_FIELDS = new Set(['margin_pct', 'wastage_pct']);

const hasBFieldChanges = useMemo(() => {
  return dirtyFields.some((field) => B_FIELDS.has(field));
}, [dirtyFields]);
```

**判斷邏輯:**
- 檢查 dirty fields 中是否包含 `margin_pct` 或 `wastage_pct`
- 回傳 `true` 或 `false`

#### E. 智能 API 呼叫（Smart API Calling）
```typescript
const onSubmit = (data: FormData) => {
  if (hasBFieldChanges) {
    // B-fields changed → Create new version via Duplicate API
    duplicateCostSheet(
      {
        margin_pct: data.margin_pct,
        wastage_pct: data.wastage_pct,
        notes: data.notes || '',
      },
      {
        onSuccess: () => {
          onOpenChange(false);
        },
      }
    );
  } else {
    // Only A-fields changed → Update same version via PATCH
    const payload: Record<string, string> = {};
    dirtyFields.forEach((field) => {
      if (A_FIELDS.has(field)) {
        payload[field] = data[field as keyof FormData];
      }
    });

    updateCostSheet(payload, {
      onSuccess: () => {
        onOpenChange(false);
      },
    });
  }
};
```

**API 選擇邏輯:**

**情境 1：只改 labor_cost**

## Known Limitations（已知限制）

### 1. A+B 混合修改時 A 欄位丟失
**問題:**
- 用戶同時改 labor_cost + margin_pct
- 系統呼叫 Duplicate API（只接受 B 欄位）
- labor_cost 的修改會丟失

**解決方案（Phase 2）:**
- Option A: 後端 Duplicate API 擴展接受 A 欄位
- Option B: 前端偵測混合修改，提示用戶分兩步操作
- Option C: 前端自動拆成兩個 API 呼叫（duplicate + patch）

**目前建議:**
- 先修改 margin → 建立新版本
- 再在新版本上修改 labor（PATCH）

---

### 2. Wastage 修改的特殊性
**目前行為:**
- Wastage 在 UI 上可以修改
- 修改後會建立新版本
- 後端會重算所有 line_cost

**潛在問題:**
- Wastage 修改影響範圍很大（所有 line costs）
- 用戶可能不清楚影響

**改進建議（Phase 2）:**
- 加強警告文字說明影響範圍
- 考慮加入「Preview Changes」功能
- 顯示修改後的 line costs 預覽
